# Yarvan data boundaries

| Surface | Input / state | What crosses the boundary |
| :--- | :--- | :--- |
| Ordinary 1:1 chat | SQLite transcript, per-bot notebook and opt-in pins | User-selected model receives the dispatched context; normal tools follow existing permission rules. |
| Project-only chat | Same-chat transcript, explicit same-scope pins, project-only JSON notebook and the same project's other chats for lexical recall | Provider gets these sources but no global memory, attached tools or reusable native session. A fork retains scope. Cross-scope moves, team sharing and widening a project-only pin are rejected. |
| Project learning | Tool-free helper call from the app using attributable user text | The selected helper provider may receive the excerpt. If it cannot make a one-off text call, automatic extraction is unavailable; the manual notebook still works. Review and learned records remain project-local. |
| Local vector ranker | Up to 64 note chunks from an admitted scope and a short query | Loopback Ollama `/api/embed` only, no redirects, capped response/time, RAM cache keyed by scope and text hash. No vector search over transcripts. A local service must actually run a local model; Yarvan cannot verify the service's own networking. |
| Telegram bridge | A Telegram bot, allowlisted numeric DM sender, distinct localhost route and ordinary per-bot API key | Text is visible to Telegram, the local app, and the selected LLM provider. No tools, no generic or UI continuation and no forking into an ordinary chat. The receiver is direct IPv4 loopback; it refuses proxy headers and is disabled with a configured public webhook URL or socket. The cursor stores only offset and a scoped thread reference. |
| Browser demonstration | Explicit start while controlling the temporary browser; a reduced interaction trace in UI memory | The submitted draft is stored as a disabled skill after review. Screens, clipboard, full URLs, field values and credentials are not collected by the recorder. It never schedules, installs an enabled skill or replays the browser. |

Project notes live in `OMB_DATA_DIR/project-memory/`, in files tied to bot and project IDs, written atomically. Deleting a bot or a project clears its current project notebook (and deleting an empty project removes its scoped pins). Forgetting a note does not rewrite the original transcript or past reply disclosures. Earlier backups and messages already sent to providers are separate copies. Do not hand a workspace backup to someone you would not trust with your transcripts and stored memory. The product preserves user access to transcript search, manual export and explicit copy. Project-only is an application context restriction, **not** an OS sandbox against a local administrator or separate programs with filesystem access.

The native export does not include the Telegram worker's local cursor/lock; run only one bridge per bot. Use non-privileged operating-system accounts and keep secrets in environment-managed configuration, outside the working tree. Neither tests nor sample data need real credentials.
