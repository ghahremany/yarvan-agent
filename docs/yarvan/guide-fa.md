# راهنمای یاروان

## پیش‌نیاز و شروع

برای بسته‌های آزمایشی ویندوز، لینوکس و همراه اندروید به [راهنمای نصب و اتصال گوشی](install-fa.md) برو. این راهنما برای محیط تک‌مالک است؛ تنظیمات فضای چندکاربره، Team/My Cloud و نسخهٔ Enterprise در دامنهٔ این انتشار نیستند. [README](../../README.md) دستور نصب وابستگی‌ها و دو ترمینال اجرا را دارد. `OMB_DATA_DIR` را بیرون مخزن، مثلاً `$HOME/.yarvan`، بگذار. باز کردن پورت‌های محلی روی اینترنت برای قابلیت‌های این نسخه لازم نیست.

### ۱. حافظهٔ فقط همین پروژه

1. کنار نام بات، پوشهٔ تازه بساز و **Project-only memory** را روشن کن. این انتخاب فقط هنگام ایجاد پروژه است. موتور سازگار با **Memory off** لازم است؛ مثلاً Claude Code به‌روز یا یک API چت سازگار. موتور ناسازگار نمی‌تواند در این چت اجرا شود.
2. گفت‌وگوی تازه را از دکمهٔ کنار همان پوشه باز کن. نوار **Project-only memory** باید بالای چت دیده شود. از تنظیمات پوشه به **Project notebook** برو و متن اولیه را با **Save project notes** ذخیره کن.
3. برای سنجاق‌کردن یک پیام یا انتخاب کوتاه از آن، مثل قبل از منوی پیام استفاده کن. بررسی کن دامنهٔ سنجاق، نام همان پروژه باشد؛ سنجاق عمومی برای این چت‌ها خوانده نمی‌شود.
4. اگر **Memory upkeep** روشن و موتورِ مناسبِ استخراج متن در دسترس باشد، بات می‌تواند یک واقعیت مستند به حرف تو را در همین پروژه یاد بگیرد. اگر **Review learned memories** روشن است، پیشنهادها در **Project notebook** همان پوشه ظاهر می‌شوند، نه صف عمومی. دکمهٔ **Reload notes** برای بارگیری پیشنهادهای جدید یا بعد از خطای هم‌زمانی است. **Keep**، **Skip** و **Forget note** روی همان فضا اثر می‌گذارند. فراموشیِ یک یادداشت متن چت اولیه یا بخش زمینهٔ پاسخ‌های قبلی را پاک نمی‌کند؛ ممکن است همان گفته از تاریخچهٔ همان پروژه دوباره پیدا شود.

**مرز:** این حالت از About me، حافظه و سنجاق عمومی، سایر پروژه‌ها، روال‌ها و ابزارهای متصل استفاده نمی‌کند. مدل هر بار از گفت‌وگوی خودش و زمینهٔ مجاز پروژه جواب می‌دهد و به نشست بومیِ قبلی وصل نمی‌شود. برای جلوگیری از ورود سابقهٔ مخلوط، نمی‌توان چت قدیمی را به این پروژه آورد یا چت پروژه را به خارج منتقل کرد. برای حذف پوشه ابتدا چت‌های آن را جداگانه حذف کن. حذف پروژه دفتر و سنجاق‌های همان پروژه را پاک می‌کند؛ سنجاقی که از این چت می‌سازی نمی‌تواند به حافظهٔ عمومی منتقل شود. اگر **چت بدون حافظه** را داخل پوشه انتخاب کنی، حتی منابع همان پروژه هم وارد نمی‌شوند.

**مثال:** دفتر پروژهٔ «سرو» را با «ضرب‌الاجل نسخه چهارشنبه است» پر کن. یک چت تازه در «سرو» و یک چت بیرون آن باز کن و در هر دو دربارهٔ موعد بپرس. در چت پروژه یادداشت باید در **Memory context** دیده شود؛ در بیرون نه. اطلاعات حساس را برای این تست استفاده نکن.

## ۲. جست‌وجوی ترکیبی محلی

پیش‌فرض جست‌وجوی کلمه‌ای است. برای رتبه‌بندی معنایی باید Ollama را جداگانه روی همان میزبان اجرا و یک مدل مناسب نصب کنی. مثال مدل چندزبانه، نه تضمین کیفیت در همهٔ دامنه‌ها:

```bash
ollama pull qwen3-embedding:0.6b
# مدل را با سرویس محلی Ollama دریافت کن. سپس اگر سرویس از قبل باز است،
# آن را با OLLAMA_NO_CLOUD=1 بازراه‌اندازی کن؛ دو نمونه هم‌زمان روی یک پورت اجرا نکن.
OLLAMA_NO_CLOUD=1 ollama serve
```

در ترمینال سرور یاروان:

```bash
YARVAN_LOCAL_EMBEDDING_MODEL=qwen3-embedding:0.6b \
  OMB_DATA_DIR="$HOME/.yarvan" OMB_DISABLE_ANNOUNCEMENTS=1 pnpm dev:server
```

اگر Ollama روی پورت دیگری گوش می‌دهد، `YARVAN_LOCAL_EMBEDDING_PORT` را بین ۱۰۲۴ و ۶۵۵۳۵ مشخص کن. مقصد همیشه `127.0.0.1` است. سرویس محلی را به پروکسی یک مدل ابری تبدیل نکن. با پاک کردن متغیر مدل و راه‌اندازی دوباره، رتبه‌بندی معنایی غیرفعال می‌شود. در دسترس نبودن Ollama باعث استفاده از جست‌وجوی کلمه‌ای می‌شود؛ نیازی به کلید بیرونی نیست. بردارها فقط در RAM هستند.

برای نمونه، یادداشتی دربارهٔ «مهلت تحویل» در یک **موضوع حافظه** یا به‌عنوان یادداشت آموخته‌شدهٔ پروژه بگذار و بپرس «تا کی باید بفرستیم؟». یادداشت‌های ثابتِ دفتر پروژه از قبل به همان پروژه داده می‌شوند؛ لازم نیست برای آن‌ها جست‌وجو انجام شود. جست‌وجوی گفت‌وگوها در این نسخه همچنان کلمه‌ای است.

## ۳. تلگرام خصوصی

1. در خودِ تلگرام یک بات اختصاصی با **BotFather** بساز. توکن را اینجا یا در GitHub وارد نکن. شناسهٔ **عددی** حساب تلگرام خودت را مشخص کن؛ نام کاربری جای شناسه را نمی‌گیرد. اگر راه مطمئن دیگری نداری، از `getUpdates` رسمی با توکنی که روی دستگاه خودت نگه می‌داری، `message.from.id` را از پیام آزمایشی خودت پیدا کن. هم‌زمان پُل دیگری یا webhook برای همان توکن فعال نباشد.
2. در یاروان یک بات جداگانه برای تلگرام بساز، حافظه‌اش را از تنظیمات بات خاموش کن، یک موتور متنی سازگار با **Memory off** انتخاب کن. **Bot API** را فعال کن و کلید تازه را یک بار ذخیره کن. **Acts as me** باید خاموش بماند. این یک کانال مکالمهٔ متنی است، نه کنترل از راه دور رایانه یا اتصال به برنامه‌ها.
3. در یک فایل **بیرون از Git** مانند `$HOME/.config/yarvan/telegram.env`، با مجوز خواندن فقط مالک (POSIX: `chmod 600`)، این نمونه را با مقادیر خودت پر کن:

```dotenv
YARVAN_TELEGRAM_TOKEN=YOUR_BOTFATHER_TOKEN
YARVAN_TELEGRAM_USER_ID=YOUR_NUMERIC_USER_ID
YARVAN_TELEGRAM_BOT_API_KEY=YOUR_ORDINARY_BOT_API_KEY
YARVAN_TELEGRAM_BOT_API_URL=http://127.0.0.1:YOUR_WEBHOOK_PORT/hooks/api/bots/YOUR_BOT_ID/telegram
```

عدد پورت را از خط **webhook receiver** لاگ سرور یا تنظیم `OMB_WEBHOOK_PORT` بردار؛ معمولاً پورتِ API سرور + ۱ است. شناسهٔ بات یاروان در آدرس کارت Bot API دیده می‌شود. انتهای URL در این پُل **`/telegram`** است، نه `/messages`. سرویس وب‌هوک را عمومی نکن. این مسیر در حضور URL عمومی یا سوکت وب‌هوک غیرفعال است و درخواست‌های پروکسی را نمی‌پذیرد.

4. روی همان میزبان و با همان `OMB_DATA_DIR` اجرا کن:

```bash
OMB_DATA_DIR="$HOME/.yarvan" \
  node --env-file="$HOME/.config/yarvan/telegram.env" scripts/yarvan-telegram.ts
```

اگر متغیرها را از سرویس سیستم یا یک محیط مطمئن وارد کرده‌ای، `pnpm yarvan:telegram` هم همان اتصال را راه می‌اندازد. به بات در **DM** پیام بفرست. `/start` و `/help` راهنما می‌دهند؛ `/reset` نشست را نو می‌کند و چت قبلی را حذف نمی‌کند. نسخهٔ محلی پیام‌ها قابل خواندن است؛ ادامهٔ همان چت فقط از تلگرام انجام می‌شود. تصویر، فایل، گروه و حساب دیگر به مدل نمی‌رسند. متن DM و پاسخ از سرویس تلگرام می‌گذرند؛ آن‌ها را چت محرمانه یا رمزنگاری سرتاسری فرض نکن. هنگام توقف ناگهانی ممکن است لازم باشد پیام بی‌پاسخ را دستی بفرستی؛ برای جلوگیری از اجرای دوباره، پُل همان پیام را خودکار بازپخش نمی‌کند. برای لغو، پُل را متوقف و کلید Bot API و در صورت لزوم توکن Telegram را عوض کن. فایل‌های نشست در `OMB_DATA_DIR/telegram/` هستند؛ اگر پس از قطع ناگهانی فایل `.lock` باقی ماند، فقط بعد از مطمئن شدن از اینکه هیچ پُلی در حال اجرا نیست آن را بردار.

## ۴. آموزش با نمایش

1. از تنظیمات مرورگر بات **Temporary / Guest** را انتخاب کن و وارد نمایش مرورگر داخلی شو. در صورت نیاز مرورگر داخلی/وابستگی‌های آن را از صفحهٔ Browser نصب کن. **Take control** را بزن.
2. با **Start demonstration** و با دادهٔ آزمایشی یک مسیر را انجام بده؛ مثلاً رفتن به صفحهٔ راهنما، پایین‌رفتن و انتخاب یک عنوان. موقع ضبط وارد حساب یا صفحهٔ پرداخت نشو. ضبط محدود به نمای یاروان است، نه مرورگر اصلی دستگاه.
3. **Stop and review** را بزن. پیش‌نویسِ مرحله‌ها را کامل کن: هدف، برچسب دکمه به‌جای مختصات، دادهٔ آزمایشی و معیار نتیجه. در این نسخه بازپخشِ کلیک یا ساخت انتخابگر از DOM خودکار نیست.
4. **Save as disabled skill** را بزن. مهارت در بخش **Skills** بات، غیرفعال می‌ماند. پس از مرور، می‌توانی آن را آگاهانه روشن کنی و در یک چت عادی با دادهٔ بی‌خطر آزمایش کنی. ضبط بدون ذخیره خودکار است؛ تغییر بات/مرورگر می‌تواند پیش‌نویس محلی را کنار بگذارد.

ضبط حداکثر ۵ دقیقه یا ۱۰۰ مرحله است؛ فقط مبدأ سایت، جای تقریبی کلیک، جهت اسکرول و اینکه داده‌ای وارد شده نگه می‌دارد. اسکرین‌شات، محتویات صفحه، مسیر و پارامتر URL، متن تایپ‌شده و اطلاعات ورود در پیش‌نویس ضبط نمی‌شوند. مبدأ سایت و جای کلیک هم ممکن است حساس باشند؛ پیش از ذخیره بررسی‌شان کن.

## از نسخهٔ قبلی چه چیزهایی باقی مانده؟

**Pin memory**، انتخاب دامنهٔ سنجاق، **Memory off**، مشاهدهٔ زمینهٔ حافظه‌ای پاسخ و صف تأیید عمومی دست‌نخورده‌اند. وضعیت **Memory off** تنها به حافظه و ابزار مربوط است، نه حذف تاریخچه یا سیاست نگهداری ارائه‌دهندهٔ مدل. حافظهٔ فقط همین پروژه هم به معنی رمزنگاری یا جداسازی فایل از مدیر سیستم نیست.
